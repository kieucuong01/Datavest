# QuantDinger 策略开发指南

> 适用范围：Strategy API V2 的研究、校验、因子分析和回测契约

QuantDinger 策略是用于研究和回测的 Python 程序。策略可以声明行情订阅、根据已完成的 K 线生成信号，并在隔离的模拟账本中评估持仓、保护规则和绩效。

最重要的边界是：**策略源码不会连接用户账户，也不会向外部交易场所提交订单。**

## 1. 推荐工作流

1. 使用公开或已授权的只读行情确定标的与周期。
2. 编写 Strategy API V2 源码并运行静态校验。
3. 在固定数据区间运行回测。
4. 检查成交假设、费用、滑点、最大回撤和样本外结果。
5. 如需持续观察，使用提醒、通知或模拟组合；这些能力仍不具备外部执行权限。

## 2. 最小策略

```python
def initialize(context):
    context.symbol = "BTC/USDT"


def handle_data(context, data):
    close = data.history(context.symbol, "close", 20)
    if len(close) < 20:
        return

    average = close.mean()
    if close.iloc[-1] > average:
        order_target_percent(context.symbol, 1.0)
    else:
        order_target_percent(context.symbol, 0.0)
```

`order_target_percent` 等函数在研究运行时产生模拟订单意图，由回测账本处理。它们不代表外部订单。

## 3. 数据与时间语义

- 只根据已完成的 K 线计算信号，避免未来函数。
- 明确声明市场、标准化标的和时间周期。
- 回测时钟来自行情数据；不要假设网络时钟或账户时钟可用。
- 公共加密货币行情连接不携带用户密钥。
- 研究代码不能读取账户余额、外部持仓、交易凭据或私有订单状态。

## 4. 信号、组合与保护规则

Strategy API V2 支持在模拟环境中表达多空信号、目标仓位、止损、止盈和组合约束。所有状态属于一次研究或回测运行。

策略应当：

- 把入场、减仓、退出条件写成可复现规则；
- 根据确认后的模拟成交推进状态；
- 对手续费、滑点、最小数量和流动性作明确假设；
- 记录不可建模的限制，并在结果中披露；
- 避免承诺收益或把历史结果描述为未来保证。

## 5. Indicator 转策略

Indicator 的 `output["signals"]` 只是图表标记。转换时必须明确每个视觉事件的含义：

- 看多入场事件可映射为 `open_long`；
- 看空退出事件可映射为 `close_long`；
- 只有在需求明确且规则独立时才生成做空入场；
- 不要仅根据标记名称推断反手逻辑。

转换后必须重新校验并在固定行情夹具上比较事件索引。

## 6. 回测验收

至少检查：

- 数据区间、时区、复权方式和缺失数据；
- 信号是否只使用当时可见的信息；
- 费用、滑点、成交价和仓位上限；
- 总收益、最大回撤、交易次数和暴露时间；
- 训练区间与样本外区间的差异；
- 参数敏感性，而不是只保留最佳参数。

回测是研究证据，不是收益承诺。研究结果、AI 输出和模拟组合都不构成投资建议。

## 7. Agent 与 MCP 边界

Agent Token 只使用 R/W/B/N 范围，覆盖研究、回测、Indicator、提醒、自选和模拟组合。MCP 客户端不能获得用户账户密钥，也不能调用外部执行能力。

新增策略工具时，应同步更新 Agent OpenAPI、MCP 声明和契约测试，并保持这一边界。
